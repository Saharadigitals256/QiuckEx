# ── Secret-detection fixtures ───────────────────────────────────────────────
# The crash-reporting redaction service needs a string shaped like a Stellar
# secret key in order to prove it redacts one. `SBZVMB74Z7…` is a well-known
# dummy value used for exactly this purpose across the Stellar ecosystem; it is
# not a funded or reachable account, and no key material is derived from it here.
# These files are test fixtures and documentation showing what a leak looks like,
# so the pattern is the subject under test rather than a finding.
app/backend/src/crash-reporting/redaction.service.unit.spec.ts | Stellar secret-key fixture for the redaction service unit test
app/backend/src/crash-reporting/crash-reporting.int.spec.ts | Stellar secret-key fixture for the redaction integration test
app/backend/src/crash-reporting/QUICK_START.md | Documentation showing a redacted secret key in an example
app/backend/src/crash-reporting/DEPLOYMENT_CHECKLIST.md | Documentation showing the grep command used to find a leaked key

# ── Deliberate exceptions ───────────────────────────────────────────────────
# The pnpm workspace requires a committed .npmrc (hoisting and workspace linking
# are load-bearing for this monorepo). The committed file carries only those
# three settings and no registry credentials; the rule stays in force so that a
# future .npmrc carrying an _authToken is still caught.
